# Migration guide: 0.2.x

Most upgrades need no action — run `agent-runner migrate` to rewrite
removed/renamed config fields to their current form, and see `CHANGELOG.md`
for per-version notes. This file collects the few manual steps a config rewrite
can't do: recovering files an old orphan-stash bug swept aside, re-generating a
systemd unit, switching to the remote event relay, and knowing where round-log
pruning leaves you.

---

## Recover deliverables swept into an orphan stash (pre-0.2.2)

Before 0.2.2, `register_plugin_owned_paths` was honored at the report boundary
but ignored at the git boundary, so `git stash push -u` could take an owned
deliverable anyway — silently, because the events and `peek` were built from the
filtered list. If any plugin registers owned paths and you upgraded across
0.2.2, check for swept files.

The stashes are still there — nothing deleted them.

```bash
# 1. List them. agent-runner's stashes carry an ORPHAN R<N> <phase> subject.
git stash list

# 2. Inspect one. --include-untracked is required: a deliverable that was
#    untracked when it was swept does not appear without it.
git stash show --include-untracked --name-only 'stash@{0}'

# 3a. Restore a file that was TRACKED and modified when it was stashed:
git checkout 'stash@{0}' -- proposals/memo.md

# 3b. Restore a file that was UNTRACKED when it was stashed. Step 3a fails on
#     these with "pathspec ... did not match any file(s) known to git" —
#     untracked entries live in the stash's third parent:
git checkout 'stash@{0}^3' -- proposals/memo.md
```

Work backwards from the newest stash. Restore individual paths rather than
`git stash pop` — a pop also restores the round's agent WIP into your tree.

## Re-generate systemd units for `KillMode=mixed` (0.2.4)

Units generated before 0.2.4 carry no `KillMode` directive, so systemd's default
`control-group` applied: `systemctl stop` delivered SIGTERM to the whole cgroup —
the round subprocess and the agent child included — killing the round instead of
letting `serve` drain it. The graceful-stop contract never actually held.

Re-run `agent-runner install` (and `install --monitor` if used) to write the
fixed unit, or add a drop-in with `KillMode=mixed` yourself. Until you do, `stop`
on an installed service still interrupts the in-flight round.

## `monitor --host` is relay-only (0.2.5)

The polling remote monitor is gone: it listed remote filenames over ssh but read
every path on the **local** filesystem, so it observed an empty world and
reported healthy. `--host` now means one thing — a managed ssh event relay,
valid only with `--mode events`:

```bash
agent-runner monitor --host pi --mode events
```

`--host` with `--mode anomaly | narrate | http` exits 1. If you ran
`monitor --host X` for detection, run the monitor **on** that host instead —
detection reads that host's round logs and metrics and its `auto_stop_on` stops
that host's service, so it keeps working with your laptop closed:

```bash
ssh X
agent-runner install --monitor          # as a systemd user unit, or
agent-runner monitor --config <path>    # in a shell
```

Relay its events to wherever you watch from.

## Where round-log pruning leaves you (0.2.6)

Round-log pruning is now opt-in: `runtime.round_log_retention` defaults to `0`,
which means never prune. Both round-log families now grow until you configure a
cap or clear them yourself. Set `round_log_retention = 100` for the pre-0.2.6
behavior. A bulk-prune guard also refuses any prune that would delete more files
than it keeps. Full rationale and the guard's fields are in
`docs/configuration.md` (§ `runtime.round_log_retention`).

By the version you are upgrading from:

- **On ≤0.2.3** — `rounds/` has never been pruned on your deployment, and after
  upgrading straight to 0.2.6+ it still will not be. Your backlog is safe by
  default; you need not raise anything before upgrading. (Upgrading *via* 0.2.4
  or 0.2.5, even briefly, runs the deletion once.) The serve-level `round-<N>.log`
  family stops being capped at 100 — set `round_log_retention` if you want that
  cap back.
- **On 0.2.4 or 0.2.5** — the `rounds/` deletion has already happened; those
  files are gone and later versions cannot bring them back. What they guarantee
  is no second pass: pruning stops entirely unless you opt in, and the bulk guard
  then stands between a lowered value and your history.
- **Anyone who wants the old behavior** — set `round_log_retention = 100`. You
  get pruning back, now with the bulk guard in front of it.

## Durable stops + agent-keyed throttle skip (0.2.11)

0.2.11 makes the safety claims hold under load. No config change — but if you run
`serve` under systemd, **re-render the unit**.

- **Re-generate the systemd unit.** Re-run `agent-runner install` (and
  `install --monitor` if used), or hand-edit the unit. Units from ≤0.2.10 carry
  `Restart=always`, which restarts `serve` even after a deliberate stop (sentinel /
  stop-file / `--max-rounds` / SIGTERM) — a give-up loop in ~3s. The new unit uses
  `Restart=on-failure` with `RestartPreventExitStatus=78 75`: a give-up stop
  (`config_broken` → 78, `crash_loop` → 75) and a clean stop stay stopped, while a
  genuine crash still restarts. Until you re-render, a stopped service may keep
  respawning.
- **Throttle-aware skip is now agent-scoped.** The skip is keyed on the **agent**
  (the binary basename of a phase's `command[0]`, matching the detector's label),
  not the phase. Every phase sharing a rate-limited agent is stepped over together,
  so a multi-provider rotation no longer takes turns hammering one throttled key,
  while a phase on a healthy provider keeps running. Behavior only: no config
  change. Caveat: two phases whose `command[0]` share a basename (e.g. two wrapper
  scripts both named `run`) are treated as one agent.
- **The all-throttled pause is reachable.** When every candidate phase is throttled
  or window-closed, the loop pauses until the earliest of a sibling window opening
  or a throttle's `reset_at`. Each agent that clears emits its own
  `transient_error_recovered` (an agent recovering while a sibling is still
  throttled still gets its breadcrumb). `peek --json` schema is `1.10`:
  `rate_limit.throttled_agents` lists every currently-throttled agent.

## Throttle-aware skip (0.2.10)

**No action required.** Additive: `phase_policy = "skip"` gains one behavior — a
phase whose provider is currently throttled (rate-limited / erroring) is stepped
over in the rotation, just as a phase with a closed schedule window already was.
A healthy sibling phase runs instead of the supervisor sleeping the whole loop on
the throttle.

- **Only `skip` routes around a throttle.** `wait`, `--ignore-schedule`, and any
  config without `[phases]` keep the pre-0.2.10 global back-off
  (`transient_error_action`) unchanged.
- **All phases blocked → wait for the earlier of window-open or reset.** When
  every phase is throttled or window-closed, the loop pauses until the earliest of
  a sibling window opening or the throttle's `reset_at`, then re-selects.
- **New observability.** `transient_error_detected` carries the failing `phase`;
  `peek --json`'s `rate_limit` shows the throttled phase; a
  `transient_error_recovered` breadcrumb closes the multi-hour skip-around event.

## Per-phase profiles (0.2.9)

**No action required.** 0.2.9 is purely additive: a config with no `[phases]`,
or with phases carrying only the pre-0.2.9 flat overrides, resolves to the
identical agent, runtime, schedule, and prompt it did before. Everything below
is opt-in.

What is new:

- **Per-phase agent and schedule.** A phase may now carry `[phases.<name>.agent]`
  (a different model or CLI for that phase — field-merged onto the base `[agent]`)
  and `[phases.<name>.schedule]` (its own pause/run windows, replacing the global
  ones). See `docs/configuration.md` (`[phases.<name>]`) for the four sub-tables
  and the never-overridable list, and `docs/runbook.md` ("Mixed-model rotation")
  for the recipe.
- **`phase_policy` = `wait` | `skip`.** New knob under `[phases]`, only meaningful
  once phases have their own schedules. `wait` (the value a config without it
  resolves to) keeps the fixed rotation and idle-sleeps a closed phase; `skip`
  steps forward to the first open phase and runs it, emitting
  `schedule_phase_skipped`.
- **Flat → nested runtime move (optional).** The flat `round_timeout_s` /
  `disable_pre_round_hooks` written directly under `[phases.<name>]` now have a
  nested home, `[phases.<name>.runtime]`. The flat form is a **permanent alias** —
  it is not deprecated and will keep working. `agent-runner migrate` *reports*
  the option to nest them (it does not rewrite them, and does nothing if you
  ignore it). Setting both the flat field and its `[phases.<name>.runtime]` twin
  is a config error — pick one.
