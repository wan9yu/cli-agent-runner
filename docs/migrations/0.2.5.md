# Migration guide: 0.2.5

## TL;DR

**One action item, for remote users only**: `monitor --host <alias>` no longer
runs anomaly detection — it is now valid *only* with `--mode events`, where it
relays the remote's event stream over a managed ssh connection. Anyone who ran
`monitor --host X` for detection must run the monitor **on** that host instead.
Nothing changes for a local monitor. Also new: `events --since` (resumable
replay) and the relay's `--kind` / `--remote-config` flags. No symbol pinned by
the public API contract was removed.

---

## Action required: `monitor --host` is relay-only

The polling remote source is deleted. It never worked: it listed remote
filenames over ssh but read every path on the **local** filesystem, so it
observed an empty world and reported healthy. 0.2.4 made it exit 1 at startup;
0.2.5 removes the machinery behind it.

`--host` now means one thing:

    agent-runner monitor --host pi --mode events

which streams the remote's events over an ssh connection agent-runner manages —
automatic reconnect with `--since <last relayed ts>` so a dropped link replays
its gap, `monitor_remote_blip` per drop, `monitor_remote_giveup` + exit 1 once
the outage passes `[monitor] remote_failure_tolerance_s`, and the ssh process
group torn down on exit. `--host` with `--mode anomaly | narrate | http` still
exits 1 (`MonitorRemoteUnsupportedError`).

If you were running `monitor --host X` for detection, run the monitor on the
host:

    ssh X
    agent-runner install --monitor          # as a systemd user unit, or
    agent-runner monitor --config <path>    # in a shell

Detection belongs there by construction: the detectors read that host's round
logs and metrics, and `auto_stop_on` stops that host's service — so detection
and auto-stop keep working with your laptop closed and the ssh session dead.
Relay its events to wherever you watch from.

## Changed: `monitor_auto_stop_failed` records a failed *local* stop

The kind is unchanged and its fields (`detector`, `error`) are unchanged, but
its meaning is re-anchored: it now records a failing local `api.stop` (unit
missing, permission denied, stale pidfile) instead of a failing stop over ssh.
The monitor records it and keeps polling rather than crashing. Grep it on the
supervised host, not on a relay client.

## Added: `events --since <ISO ts>`

    agent-runner events --kind round_end --since 2026-07-27T10:00:00.000Z
    agent-runner events --kind round_end --tail --since 2026-07-27T10:00:00.000Z

Emits every matching event with `ts >= since`, across month files, then follows
if `--tail` was given. At-least-once by contract: reconnect with the last `ts`
you saw and that one event may repeat, but nothing that fired while you were
disconnected is lost. This replaces hand-rolled reconnect loops, which restarted
the tail from *now* and silently dropped the gap. `--since` is mutually
exclusive with `--window`.

## Added: relay flags `--kind` / `--remote-config`

Both apply to `--host --mode events` only; passing either elsewhere exits 1.

- `--kind K[,K2,…]` — kinds to relay. The default is every kind **this client**
  knows: built-ins plus plugin kinds installed locally. A kind that exists only
  on the remote (a plugin installed there but not here) is not in that set and
  must be named explicitly.
- `--remote-config PATH` — config path on the *remote* host. Omitted by default,
  so the remote resolves `./agent-runner.toml` in the ssh landing directory. The
  client's own `--config` still names the log dir where the relay writes its
  blip / give-up telemetry.

## Removed: the polling remote API surface

`monitor.RemoteSource`, `monitor.run_remote_command` and
`monitor.MonitorRemoteError` are gone, along with `on_alert`'s `host` parameter
and the `host` field on `monitor_auto_stop_triggered`.

To be precise about the blast radius: none of these were part of the pinned
public API surface. `tests/contract/test_public_api_surface.py` pins
`agent_runner.monitor` at `AUTO_STOP_ALERTS`, `KNOWN_ALERT_KINDS`,
`register_detector` and `plugin_detectors` — the plugin-author contract — and
that set is untouched. The removed names were importable but never contracted,
so a plugin built against the documented surface is unaffected; out-of-tree code
that reached past it gets an `ImportError`. There is no replacement: remote
detection is not coming back.

## Also in this release

Docs re-anchored to the relay model (`docs/runbook.md` § "Remote event relay &
SSH trust", `docs/architecture.md` § "Remote observation"), and the `upgrade`
verb's smoke coverage is now stated explicitly — what it checks per install
