# Migration guide: 0.2.4

## TL;DR

No public symbols removed. Two detector plugins (`kimi_error_detector`,
`pi_error_detector`) activate automatically, one new event kind
(`agent_auth_error_detected`), and four behavior fixes. **Two items need
action**: existing systemd installs should re-run `agent-runner install`
(KillMode fix), and operators who keep old agent round logs should raise
`round_log_retention` *before* upgrading (pruning now applies to `rounds/`).

---

## Action required: re-generate systemd units (`KillMode=mixed`)

Units generated before 0.2.4 carry no `KillMode` directive, so systemd's
default `control-group` applied: `systemctl stop` delivered SIGTERM to the
whole cgroup — the round subprocess and the agent child included — which
killed the round immediately instead of letting `serve` drain it. The
graceful-stop contract (`KillSignal` + `TimeoutStopSec`) never actually held.

Re-run `agent-runner install` (and `install --monitor` if used) to write the
fixed unit, or add a drop-in with `KillMode=mixed` yourself. Until you do,
`stop` on an installed service still interrupts the in-flight round.

## Action if you keep round-log history: `rounds/` is now pruned

`{log_dir}/rounds/R<N>-*.log` (the agent's merged stdout+stderr, one file per
round) previously grew without bound. From 0.2.4 the newest
`runtime.round_log_retention` files (default **100**) are kept and older ones
are deleted at the start of every round. If you rely on older transcripts,
raise `round_log_retention` before the first post-upgrade round runs.

## Changed: relative `work_dir` anchors to the config file's directory

`work_dir = "."` (all presets) now resolves against the directory containing
`agent-runner.toml`, not the caller's cwd — `agent-runner round --config
/abs/proj/agent-runner.toml` drives `/abs/proj` from anywhere. Setups that
launched from inside the project directory (the documented layouts, including
generated systemd units) are unaffected.

## Changed: `monitor --host` now fails loudly

Remote monitor mode listed remote filenames but read every path locally — it
observed an empty world and reported healthy. It now exits 1 at startup with
guidance to run the monitor on the supervised host. A resumable remote event
stream is planned as the replacement (`events --since` + a managed ssh relay).

## Added: kimi and pi detector plugins, structured auth events

- Rounds run under the `kimi` / `pi` presets now emit `transient_error_detected`
  (both) and `agent_usage_recorded` (pi only — kimi's stream carries no token
  counters), driving the serve loop's back-off and `rate_limit_active` like the
  claude/gemini/codewhale plugins already did. Disable via `[plugins] disable`
  if unwanted.
- New `agent_auth_error_detected` event: a plugin reports an auth failure named
  by the agent CLI's own structured output; `detect_oauth_fail` counts those
  rounds directly (no nonzero-exit requirement — the CLI's own verdict needs no
  heuristic gate). This makes a pi 401 loop auto-stop the service; pi exits 0
  on provider failure, so the text-heuristic path alone could never see it.

## Also in this release

Round-log tail scanning hardened (JSON pre-filter, shared 200-line window,
bounded monitor reads); startup command validation now mirrors the spawn's
exact resolution (child PATH, `work_dir` base); `PWD` pinned to `work_dir`.
