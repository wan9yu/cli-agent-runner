# Migration guide: 0.2.7

## TL;DR

**New opt-in `[schedule]` section gates the serve loop against a wall clock.**
Add `pause_windows` (and optionally `run_windows` + `timezone`) to pause the
supervisor during configured time windows — for example, a provider's
peak-pricing hours — and auto-resume when the window closes. **No migration is
required:** omit the section and serve runs 7×24 exactly as it did in 0.2.6. No
public symbols were removed; two new event kinds (`schedule_paused`,
`schedule_resumed`) and one new flag (`serve --ignore-schedule`).

---

## What it does

Between rounds — never mid-round — the serve loop asks whether the current
instant is runnable. If not, it emits `schedule_paused`, idle-sleeps until a
window opens, then emits `schedule_resumed` and continues. A round already in
flight when a window boundary passes runs to completion; scheduling only decides
whether to *start* the next one. `agent-runner round` (a manual, one-shot round)
is never gated.

```toml
[schedule]
timezone = "Asia/Shanghai"
pause_windows = ["Mon-Fri 09:00-12:00", "Mon-Fri 14:00-18:00"]
```

This is the current DeepSeek off-peak policy: rounds pause through the
provider's Mon–Fri peak hours and run at all other hours, including the full
weekend.

## Window syntax: `[WEEKDAYS ]HH:MM-HH:MM`

- **24-hour `HH:MM`, end-exclusive.** `09:00-12:00` covers 09:00 through 11:59
  and reopens at 12:00.
- **`24:00`** is valid only as an end bound (end-of-day); `00:00-24:00` is the
  whole day. Start must not equal end.
- **Midnight wrap.** A window whose end is at or before its start wraps past
  midnight: `22:00-02:00` covers 22:00–23:59 and 00:00–01:59 the next morning.

### Optional weekday prefix

- Tokens `Mon Tue Wed Thu Fri Sat Sun`, case-insensitive.
- Range `Mon-Fri` (ascending only; `Fri-Mon` is rejected), list `Sat,Sun`,
  combination `Mon-Fri,Sun`.
- **No prefix = every day.**
- For a wrapping window, the early-morning tail belongs to the window's **start**
  day: `Fri 22:00-02:00` covers Friday night and early Saturday, not Saturday
  night.

## Evaluation rule: `run AND NOT pause`

An instant is runnable when it is inside a run window **and not** inside any
pause window:

- `run_windows` empty (the default) → every time is runnable, so only
  `pause_windows` carve out exceptions. This is the documented recipe for this
  release.
- `run_windows` set → serve runs only inside a run window, minus any overlapping
  pause window. `run_windows` is fully supported (forward-compatible); the
  pause-based form is what this guide's examples use.
- `timezone` is an IANA name; omit it to evaluate in the supervisor host's local
  time. An unknown zone is rejected at config load.

## Events

Both land in the normal event stream (`events-YYYY-MM.jsonl`).

`schedule_paused` — emitted when serve enters a pause:

| Field | Meaning |
|---|---|
| `active_window` | the window label that caused the pause, e.g. `"Mon-Fri 09:00-12:00"` (or `"outside run_windows"` when a `run_windows`-only gap is responsible) |
| `resume_at` | ISO-8601 timestamp when the window next opens (empty string if none within the 8-day search horizon) |
| `timezone` | the configured zone, or `"local"` when unset |

`schedule_resumed` — emitted when the window actually opens:

| Field | Meaning |
|---|---|
| `paused_for_s` | integer seconds the loop was paused |

An interrupted pause (SIGTERM/SIGINT during the sleep) is a termination, not a
resume: it leaves `schedule_paused` as the newest event and emits no
`schedule_resumed`.

## `peek` surfaces the pause state

`agent-runner peek` reports the current pause via a `schedule` field — present
in `peek --json` and in the generic pretty output. It is populated while paused
(carrying `paused`, `resume_at`, `active_window`) and `null`/absent once
resumed, so an operator can see `paused until <resume_at>` at a glance.

## Monitor interaction

The `supervisor_stale` detector no longer false-alarms during an intentional
pause. A pause is deliberate silence, so while the newest schedule event is a
`schedule_paused`, staleness is suppressed — but only until `resume_at` plus one
staleness window. A supervisor that genuinely died mid-pause therefore still
alarms once that bound passes; the suppression is bounded, not open-ended.

## Forced catch-up: `serve --ignore-schedule`

To run regardless of the windows — draining a backlog, or testing — start serve
with `--ignore-schedule`:

```bash
agent-runner serve --config /etc/agent-runner.toml --ignore-schedule
```

The flag bypasses the gate entirely: no `schedule_paused` is emitted even when a
pause window is active. It defaults to off.

## Nothing to change on upgrade

- **No `[schedule]` section** → identical behavior to 0.2.6; the gate is inert.
- **Adding `[schedule]`** is purely additive and takes effect on the next serve
  start (config is read once at startup, as with every other section — run
  `agent-runner restart` to pick it up).
